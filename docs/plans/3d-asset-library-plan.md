# 3D 资产库与精细场景视频生成方案

- 日期：2026-10-16
- 文档状态：已授权开始实施；第一阶段主流程已开发，完整验收进行中
- 技术边界：Tauri / Rust、SQLite、Radix UI、Tailwind、Blender MCP、Orillusion / WebGPU
- 实施记录：用户已明确要求“先按功能提交代码，然后开始实现该 md”。原三轮评估记录保留，最新进度见第 11 节。

## 1. 目标与现状

建立可长期复用的 3D 资产库，让用户通过应用导入人物、建筑、家具等模型，由应用完成检查、分类、预览和索引；生成场景时选择已经登记的资产，由 Blender 完成组装、动画和正式渲染，结果进入现有画布与时间线。

当前已存在 `~/Documents/editor-tarui/assets/3d-library/` 目录及启动初始化逻辑，但没有完整的资产管理、入库、检索与匹配功能。现有 Blender 生成输出位于 `assets/blender/<任务号>/`。本方案中的新增功能均为待实施，不应把目录存在视为资产库已经完成。

### 1.1 预期收益

- 精细模型制作或导入一次，多次使用，减少方块拼装和重复建模。
- 跨镜头固定资产 ID 与版本，保持人物、建筑及道具一致。
- 显示匹配理由和能力缺口，允许用户替换资产。
- 保留 Blender 制作信息，实时预览不限制最终渲染质量。

### 1.2 非目标

第一版不支持任意人物自动绑定、任意骨骼动作迁移、精细模型自动生成、复杂室内通行分析、资产商店或云端同步。不能承诺把任意 Blender 文件无损转换为 GLB，也不保证实时预览与离线渲染逐像素一致。

## 2. 模块与用户流程

在“体验功能”增加独立“3D 资产库”入口，与“文本生成 3D 动画”并列。资产库跨项目共享，项目仅引用确定的资产版本。

| 模块 | 职责 |
| --- | --- |
| 资产库 | 导入、检查、分类、预览、搜索、版本管理 |
| 场景生成 | 拆解需求、检索候选、确认选用、布局与镜头编排 |
| Blender | 解析源文件、制作版本、组装场景、动画与渲染 |
| 画布与时间线 | 接收视频素材并继续编辑 |

### 2.1 页面结构

- 顶部：搜索、导入资产、扫描未登记文件、导入任务。
- 左侧：全部、人物、建筑、家具、植物、交通工具、道具、其他。
- 中间：缩略图、名称、风格、状态、动画能力标识。
- 右侧详情：预览、描述、标签、尺寸、材质、动画、版本、来源、技术信息。
- 筛选：分类、风格、可用状态、动画能力、缺失依赖。

主界面不堆积面数等实现细节；技术信息用于判断资产适用性。继续使用 Radix UI 与 Tailwind，不引入新的组件库。

### 2.2 导入流程

```text
选择/拖入文件或扫描未登记文件
→ 格式检查与重复检测
→ 通过 Blender 解析模型及依赖
→ 选择整个文件或一个 Collection
→ 补齐依赖、确认尺寸和朝向
→ 复制并整理源文件、生成制作版本
→ 生成缩略图与可用的 GLB 预览
→ 确认分类、风格、能力和来源
→ 提交索引，成为可用资产
```

第一版支持 `.blend` 和 `.glb`。不原地修改用户原文件；`.blend` 可包含多个物体，允许导入整个文件或一个 Collection，暂不支持自动拆分出多个语义资产。

外部纹理、链接库等依赖必须检查。缺失时显示文件列表，允许选择替代路径或保留任务等待补全，不得把复制完成当成入库成功。

### 2.3 状态设计

| 状态 | 用户可执行操作 | 自动匹配 |
| --- | --- | --- |
| 等待处理 | 取消、查看队列 | 否 |
| 等待 Blender | 连接后继续、取消 | 否 |
| 正在解析/整理 | 查看进度、请求取消 | 否 |
| 需要补全 | 补文件、修正信息、取消 | 否 |
| 正在生成预览 | 查看进度、请求取消 | 否 |
| 可使用 | 预览、修改标签、创建新版本、停用 | 是 |
| 导入失败 | 查看具体原因、重试、移除失败任务 | 否 |
| 已停用 | 恢复使用、检查项目引用 | 否 |

取消是请求，不假定 MCP 调用立即停止。只有 Blender 已完成或确认终止，才能清理任务文件和释放执行槽位。

## 3. 资产档案与质量检查

| 信息 | 获取方式 | 用途 |
| --- | --- | --- |
| 名称、分类、描述、标签 | 预填后由用户确认 | 检索与展示 |
| 风格、外观 | 人工确认；后续可辅助识别 | 保持场景一致 |
| 尺寸、单位、正面、原点 | 自动检测并允许校正 | 布局与落地 |
| 网格、材质、纹理、骨骼 | Blender 提取 | 技术检查 |
| 动画名称、时长、动作语义 | 自动提取片段，人工确认语义 | 动作选择 |
| 室内空间、入口、可活动部件 | 人工确认或专项验证 | 能力过滤 |
| 来源、作者、授权说明 | 用户填写或随资产导入 | 使用条件记录 |
| 资产 ID、版本、指纹、路径 | 应用生成 | 稳定引用与去重 |

“检测到”与“已确认”分开记录：存在 Walk 片段不等于验证可行走，建筑外观也不能证明存在可用室内。未确认能力不满足强制需求。

### 3.1 独立能力状态与导入确认

资产状态之外分别保存：`render_status`（Blender 制作/渲染可用性）、`preview_status`（GLB/缩略图/低清视频预览能力）、`animation_status`（动作检测与验证结果）。

- 原始文件和依赖完整、Blender 可使用，且必要信息已确认，即可成为正式渲染候选。
- GLB 转换失败不删除源文件，不把资产整体标为失败；展示“仅 Blender 预览”，允许重试转换。
- 动画未验证的角色可以用于静态镜头，但不能自动满足行走需求。
- 确认页显示换算后的米制尺寸、正面方向和落地点。校正作用于制作版本，保留源文件。
- 用户需要补资料时保留已完成阶段；重新打开任务可继续，不从头复制。
- 第一版采用人工确认标签，不依赖外部视觉 API；后续辅助标注需明确服务和数据发送范围。

### 3.2 分类检查

- 人物：身高、脚底原点、朝向、骨骼、动作片段、服装材质。首版支持静态角色与附带动作角色的入库；动作可播放性按实际预览和 Blender 验证记录。
- 建筑：尺寸、外壳/室内、入口、适用内景或外景；入口与通行能力首版人工确认。
- 家具：尺寸、放置原点、使用朝向、材质和活动部件。
- 植物：尺寸、透明贴图、复杂度、风动动画。

### 3.3 三类产物

1. 原始源文件及依赖：保留可追溯的输入。
2. Blender 制作版本：整理为可导入的 Collection，收集依赖，不破坏原始文件。
3. 预览版本：GLB 和缩略图；可以降低网格与纹理预算，但必须标注与正式模型的差异。

## 4. 资产匹配

### 4.1 流程

```text
文本描述 → 结构化资产需求 → 必要条件过滤 → 候选排序
→ 展示匹配结果 → 用户确认/替换 → 固定资产 ID 与版本 → Blender 组装
```

必要条件包括类别、可用状态、要求的风格、动作能力、室内需求和用户规定的使用条件。候选再按描述、标签、尺寸、镜头距离、调整成本及项目既有选用排序。

首版使用 SQLite 文本检索、标签和中英文别名；后续资产规模需要时增加语义检索。不能用向量相似度替代能力验证。

| 需求 | 结果 | 展示内容 |
| --- | --- | --- |
| 站立休闲人物 | 人物 A v1 | 外观符合、站立能力已确认 |
| 可进入的住宅 | 住宅 B v2 | 有室内、入口已确认 |
| 红色外套人物 | 人物 C v1 | 需要修改服装材质，待确认 |
| 特殊雕塑 | 无匹配 | 导入、换候选或明确选择草稿占位 |

无匹配时不自动生成方块替代品。首版匹配结果统一确认后生成；后续可提供显式的自动选用选项。

### 4.2 跨镜头一致性

资产角色与资产版本绑定，例如“主角”固定到人物 A v1。检索不能在后续镜头中自动替换角色。颜色、姿态等场景调整属于实例覆盖，不写回共享源资产；用户要求更新资产时创建新版本。

## 5. 存储与数据设计

```text
editor-tarui/
├── assets/
│   ├── 3d-library/<资产ID>/<版本ID>/
│   │   ├── source/       原始模型与依赖
│   │   ├── prepared/     Blender 制作版本
│   │   └── preview/      GLB 与缩略图
│   └── blender/<任务ID>/ 场景与渲染输出
└── sqlite/assets3d.db    资产库索引、任务与能力信息
```

路径由后端统一解析，前端使用相对路径和现有 `getAssetSrc()`，不使用 `file://`。原始模型与制作版本属于长期资产，不纳入普通缓存清理。预览可重建，但必须保留重建所需输入和处理版本。

| 表 | 职责 |
| --- | --- |
| assets | 资产 ID、名称、分类、状态、当前版本 |
| asset_versions | 版本 ID、描述、尺寸、生成时间、处理器版本 |
| asset_files | 相对路径、用途、大小、内容指纹 |
| asset_tags | 标签与检索字段 |
| asset_capabilities | 能力、验证状态及依据 |
| asset_animations | 动画片段、时长、动作语义 |
| import_jobs | 状态、阶段、错误、重试与恢复信息 |

采用独立 SQLite 连接和锁，不使用跨库 JOIN、ATTACH 或跨库事务。数据库结构与迁移使用临时数据库验证，不操作真实用户数据。

版本不可变；修改模型或制作参数产生新版本。手动放入目录的文件仅被扫描发现，仍需走统一入库流程。重复导入提供“使用已有资产 / 创建新版本”，不擅自覆盖。

### 5.1 文件与数据库一致性

SQLite 事务不能原子提交文件系统操作，因此采用可恢复的阶段提交，不宣称跨文件/数据库原子性：

1. 建立任务记录，在资产库内部 `.imports/<任务ID>/` 准备文件，不使用系统临时目录保存正式资产。
2. 复制依赖并校验完整性，记录阶段、文件指纹和处理版本；未完成内容不参与检索。
3. 在同一文件系统内将完整目录重命名到最终版本目录；目标存在则停止，不覆盖。
4. 在 `assets3d.db` 单一事务中写入版本、文件、标签、能力，并将任务标记完成。
5. 启动时检查未完成任务：目录已就位但索引未提交的任务可幂等继续；源文件缺失或校验失败时转入待修复，不盲删目录。

任务 ID 与资产版本 ID 唯一；重试不得创建重复版本。去重分两步：源文件指纹用于早期提示，完整依赖清单及内容指纹、所选 Collection 和整理参数共同决定版本是否相同。纹理改变但 `.blend` 未变，仍可能产生新版本。

### 5.2 引用、删除与维护

项目所属数据库记录资产 ID、版本 ID、实例覆盖。资产服务通过应用层接口检查引用，不跨库查询或事务。由于引用检查与删除存在竞争，第一版只提供停用，不提供已发布版本的物理删除；垃圾清理仅处理确认已停止的未完成导入任务。后续实现物理删除前，必须补齐引用协调和在途任务保护。

备份应包含数据库和 `source/prepared` 文件，预览可选择重建。手工移走文件时将版本标记为缺失并显示修复入口，不悄悄换成另一个版本。

路径按后端生成的 ID 组织，不把用户文件名直接拼接成目录。收集依赖时处理重名文件和相对引用，复制后重新绑定路径。解析 `.blend` 使用受控脚本，不自动执行资产内嵌 Python。

### 5.3 跨进程目录权限

应用和 Blender 都必须检查实际任务目录的读写能力；“应用可创建目录”不代表 Blender 可写。准备阶段分别探测，失败时展示具体路径与进程身份，不重复生成、不靠扩大所有资产目录权限处理。首版优先在相同登录用户下运行应用和 Blender；历史目录所有者异常通过明确的修复流程解决。

## 6. Blender 执行与视频链路

导入、预览转换、场景生成与渲染共享任务调度。首版同一 Blender 实例串行处理，避免并发修改上下文；独立任务场景不覆盖用户正在编辑的场景。

```text
确定资产版本 → 导入制作版本 → 布局、材质、动作、镜头
→ 快速预览与检查 → Blender 正式渲染图像序列
→ 视频编码 → 登记为素材 → 加入画布或时间线
```

### 6.1 执行边界

MCP 作为命令与状态入口，不把长渲染寄托在一次阻塞调用中。进入视频阶段前，需验证异步任务 ID、阶段查询、取消请求与结果落盘协议；必要时使用独立 Blender 后台进程执行长渲染，继续复用现有 Blender 技术栈。后台处理不接管用户当前 `.blend`。

网络超时仅表示未收到结果，不代表任务终止。超时任务标记为状态待确认，禁止立刻重试同一任务或释放同一 Blender 实例给下一任务，直到核对进程/任务状态。

只有资产版本、场景、动作、相机、分辨率、帧率、渲染设置与执行版本一致时，才允许复用已有渲染帧。编码成功后检查视频可读性、时长及帧数，再登记素材；素材登记失败只重试登记，不重新渲染。

正式渲染支持后续选择 Eevee 或 Cycles。优先图像序列再编码，长任务中断可保留已完成帧。复杂 Blender 效果无法用 GLB 表达时，使用 Blender 低清帧或视频预览。

## 7. 分阶段实施

| 阶段 | 范围 | 明确不包含 |
| --- | --- | --- |
| 一：入库 | 页面、GLB/Blend 导入、依赖检查、缩略图、索引、编辑标签、搜索 | 自动语义匹配、视频渲染 |

首个验证样例为风格一致的人物、树木、长椅、地面组成的小广场。真实模型文件需在实施前准备，不把示例名称视为已具备资产。

## 8. 验收基线

- 导入后重启应用，资产索引、预览与文件引用仍然有效。
- 缺纹理和缺链接文件有明确提示，不能进入自动匹配。
- 重复导入可识别；新版本不覆盖旧版本。
- 取消、Blender 断连和进程异常可恢复，不误删已有资产。
- SQLite 迁移验证保留数据、隔离、失败回滚、幂等与重开持久性。
- 无匹配时需要用户决定，不静默降级。
- 相同角色跨镜头保持同一版本，实例修改不污染共享资产。
- 视频生成失败保留可恢复的帧与错误信息，不登记损坏视频为成功素材。

### 8.1 可执行验收矩阵

| 编号 | 阶段与样本 | 操作 | 通过条件 |
| --- | --- | --- | --- |
| A01 | 一：自包含 GLB 家具 | 导入、关闭并重开应用 | 分类、尺寸、文件、缩略图可恢复，预览可打开 |
| A02 | 一：带外部贴图的 Blend | 故意移走一张依赖再导入 | 显示具体缺失文件，补齐后可续办，不出现假成功 |
| A03 | 一：多 Collection 文件 | 只选择长椅 Collection | 制作版本只包含所选资产及其必要依赖，原文件不变 |
| A04 | 一：复杂材质 Blend | 模拟 GLB 转换失败 | 源资产保留，可用 Blender 缩略图预览，实时预览降级被标明 |
| A05 | 一：单位和方向不同的模型 | 校正尺寸、朝向及落地点 | 制作版本尺寸符合确认值，源文件指纹不变 |
| A06 | 一：重复与变更依赖 | 重复导入，再只修改纹理导入 | 相同输入提示复用；依赖变化可以创建新版本 |
| A07 | 一：导入阶段故障 | 在复制、目录就位、索引提交处分别中断 | 重开后可继续或明确修复，不重复发布、不误删已发布版本 |
| A08 | 一：目录权限差异 | 模拟应用可写而 Blender 不可写 | 建模前报出路径与写入问题，不反复重试 |
| A09 | 一：SQLite 迁移 | 临时库执行、故障回滚、重开、重复执行 | 数据保留、功能隔离、回滚和幂等全部通过 |

| B03 | 二：两个镜头复用主角 | 修改其中一个实例衣色 | 资产版本固定，共享源文件与另一个实例不被改写 |
| C01 | 三：短镜头正式渲染 | 渲染图像序列、编码、登记素材 | 帧数、时长和输出路径符合任务，画布可播放 |

| C03 | 三：MCP 超时与取消 | 超时后提交重试或下一个任务 | 先确认原任务状态，不并发接管同一实例 |

第一阶段完成 A01～A09 后再进入第二阶段；第二阶段完成 B01～B03 后再进入视频阶段。每阶段需同时通过相关类型检查、构建、自动测试及真实 Blender/桌面应用验证。性能先在用户实际机器上记录导入时长、峰值内存、预览帧率和资产规模，再确定预算，不承诺未经测量的耗时。

## 9. 三轮评估记录

### 第一轮：功能与用户流程

评估方式：沿“精细人物导入 → 建筑依赖缺失 → 用户修正 → 场景匹配”逐步检查。

| 发现 | 风险 | 已落实的修订 |
| --- | --- | --- |
| 入库状态与 GLB 预览混在一起 | 合法 Blender 资产可能因预览转换失败而被拒绝 | 拆分渲染、实时预览和动作状态 |
| 尺寸校正缺少确认环节 | 厘米模型被当成米，场景比例错误 | 增加单位、落地、朝向确认 |
| 自动标注容易被当成事实 | 错选不能进入的建筑或没有动作的人物 | 未验证能力不满足强制条件，保留人工确认 |

结论：功能流程可形成闭环；精细资产不能被实时预览兼容性限制。上述修订纳入正文，尚非功能验收。

### 第二轮：技术与数据可靠性

评估方式：检查数据库职责、文件提交时序、重试去重、项目引用及 Blender 跨进程执行。

| 发现 | 风险 | 已落实的修订 |
| --- | --- | --- |
| 只描述数据库事务，没有文件恢复协议 | 断电后索引与目录不一致 | 增加同盘准备目录、阶段提交与启动恢复 |
| 只按源文件去重 | 纹理变化被误认为重复 | 加入依赖指纹、Collection 和处理参数 |
| 跨库引用检查存在删除竞争 | 已用模型被删除 | 首版仅停用，物理删除后置 |
| MCP 超时等同任务失败 | 重试并发修改 Blender | 增加状态待确认、执行槽位保护 |
| 同目录不等于同写权限 | 重复发生导出 PermissionError | 应用与 Blender 分别探测目录权限 |
| 长渲染与当前编辑会话混用 | 会话阻塞或覆盖用户内容 | 明确隔离和异步任务协议的技术验证门槛 |

结论：存储和执行边界已明确；后台任务取消及恢复能力仍须在实施阶段通过真实 Blender 实验验证，本文不声称已经具备。

### 第三轮：实施范围与验收标准

评估方式：将每项承诺映射到样本、操作、通过条件，检查阶段边界与未决依赖。

| 发现 | 风险 | 已落实的修订 |
| --- | --- | --- |
| 验收描述偏笼统 | “能导入”掩盖依赖与恢复缺陷 | 增加 A01～C03 的具体验收矩阵 |
| 首版与远期能力边界容易混淆 | 未完成入库就同时开发视频和动作迁移 | 增加逐阶段准入门槛 |
| 高质量资产尚未准备 | 测试只用方块却宣称精细模型可用 | 列明真实样本准备要求 |
| 性能和兼容性缺少实测依据 | 给出不可靠时长或全格式兼容承诺 | 记录测量项，明确技术验证与未决项 |

结论：方案已具备分阶段实施与验收依据。三轮评估属于本次文档自审，不是独立多人评审，也不是已实现功能的测试报告。当前仍为待用户授权的设计方案。
